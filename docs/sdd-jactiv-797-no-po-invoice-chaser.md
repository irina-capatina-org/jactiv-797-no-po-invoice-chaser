## 1. API Workflow Overview

Runs unattended on weekdays at 10:00 Romania time. Queries Coupa for invoices from the past seven days with status draft or new, excludes credit notes, counts those without a properly linked PO, and sends one Slack Block Kit DM to AP SME with the count if count > 0; sends nothing when count = 0 (BR-07).

**Trigger:** Orchestrator schedule, weekdays 10:00 Romania time.  
**Outcome:** Slack Block Kit DM to member ID WLX9BD8FN when qualifying_count > 0.

| Field | Type | Required | Purpose |

## 3. Output Schema

| Field | Type | Purpose |
|---|---|---|
| `status` | string | `Successful` (happy path); on error, run fails and Orchestrator marks it as failed. |
| `qualifying_count` | number | Count of draft/new invoices from the past 7 days with no linked PO, after credit-note exclusion. |
| `slack_sent` | boolean | `true` if qualifying_count > 0 and Slack message was delivered; `false` otherwise. |

## 4. Execution Flow

| Step | Activity type | Input | Output | Notes |
|---|---|---|---|---|
| 1 | Assign | workflow start | variables initialized | Window computation via JsInvoke: windowStart = today − 7, windowEnd = today, runDate = today (YYYY-MM-DD). (BR-04) |
| 2 | HTTP Request (Coupa) | windowStart, windowEnd | invoices[] | Query `invoices` with `status[in]=draft,new`, date bounds, limit 50. Connection: `coupa-uipath-test` (5fadfc73-a372-46ae-a27c-2481741eed07). (BR-04) |
| 3 | JsInvoke | invoices[] | qualifyingCount, exclusionLog | Exclude credit notes (B1: `invoice-type === "Credit Note"`) and invoices with linked PO (B2: `po-number` or `order-header-num` non-empty). (BR-01, BR-02, BR-03, BR-05) |
| 4 | If qualifyingCount > 0 | (none) | branch | B3: if count = 0, skip to logging; else compose Slack payload and URL, POST to Slack, validate ok, set slackSent. (BR-07) |
| 5 | JsInvoke | count, slackSent | log output | Log qualifying_count and slack_sent to console. (BR-08) |
| 6 | Response | variables | status, qualifying_count, slack_sent | Return success. |

## 6. Error Handling

| System error | Trigger | Detection | Response | Notified |
|---|---|---|---|---|
| S1 — Coupa auth fails | Cannot acquire token | HTTP 403 or exception | Log; fail run | Orchestrator log |
| S2 — Coupa query fails | API returns error | HTTP non-200 or parse exception | Log; fail run | Orchestrator log |
| S3 — Slack delivery fails | HTTP returns error | HTTP non-200 or ok !== true | Log; throw; fail run | Orchestrator log |
| S4 — Timeout/unreachable | System down or network loss | Connection timeout or exception | Log; fail run | Orchestrator log |
| S5, S6 — Any other failure | Script or activity throws | Exception bubbles | Log; fail run | Orchestrator log |

No retry specified—the PDD describes no transient failure or fallback. Failed runs are reported to Orchestrator only; no secondary notification (BR-08, BR-09).

## 8. Testing Strategy

### Happy Path

| Scenario | Given | When | Then |
|---|---|---|---|
| Clean day | Zero qualifying invoices | Execute | `qualifying_count = 0`, `slack_sent = false`, no Slack call |
| Invoices found | 3+ draft invoices, no credit notes, all no linked PO | Execute | `qualifying_count > 0`, `slack_sent = true`, Block Kit sent |

### Business Exceptions

| Exception | Trigger | Check |
|---|---|---|
| Credit notes | `invoice-type = "Credit Note"` | Excluded from count; logged |
| PO description-only | `po-number` empty, PO in description | Counted as qualifying |

### System Errors

| Error | Trigger | Check |
|---|---|---|
| Coupa fail | 403/5xx or unreachable | Run marked failed; no Slack sent |
| Slack fail | 4xx/5xx or ok !== true | Run marked failed; error logged |
